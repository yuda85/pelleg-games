# PWA and GitHub Pages

## Installable, offline PWA

`@angular/service-worker` with [ngsw-config.json](../ngsw-config.json). Three
asset groups:

| Group          | Mode     | Contents                                     |
| -------------- | -------- | -------------------------------------------- |
| `app`          | prefetch | index, css, js, manifest, `media/**` (fonts) |
| `lazy-screens` | prefetch | every `chunk-*.js` route bundle              |
| `icons`        | lazy     | images and any remaining font files          |

Route chunks are **prefetched**, not lazy — a child who installs the app on the
hub screen and then loses signal can still open the game.

Icons are generated by [tools/make-icons.mjs](../tools/make-icons.mjs)
(`npm run icons`). It rasterises the droplet and writes the PNG itself, so there
is no image toolchain to install. Every size is drawn maskable-safe (art inside
the middle 62%) and declared `any maskable`, so one file works cropped or not.

The manifest is Hebrew, `dir: rtl`, `display: standalone`, portrait, with a
shortcut straight into the nikud game.

## Deploying

Pushing to `main` runs [.github/workflows/deploy.yml](../.github/workflows/deploy.yml):
tests, then build, then publish to Pages.

One-time setup: **Settings → Pages → Source: GitHub Actions.**

Two things Pages needs that a normal build does not:

1. **`--base-href`.** The site is served from `/<repo>/`, not `/`. The workflow
   passes `BASE_HREF=/${{ github.event.repository.name }}/` so it always matches
   the repo name. Locally, `npm run build:pages` defaults to `/Pelleg/`; override
   with `BASE_HREF=/other-name/ npm run build:pages`.

   Font URLs in CSS are **relative** (`./media/…`) rather than absolute, because
   CSS `url()` resolves against the stylesheet, not `<base href>` — an absolute
   `/fonts/…` would break under a subpath.

2. **`404.html`.** Pages is a static host with no rewrite rules, so a deep link
   like `/Pelleg/nikud/2` would 404. Pages serves `404.html` for any miss, so
   [tools/pages-postbuild.mjs](../tools/pages-postbuild.mjs) copies `index.html`
   to `404.html`, which boots the router on the requested URL. It also writes
   `.nojekyll`, without which Jekyll drops any path starting with `_`.

## Checking the subpath build locally

`npm run build:pages` alone serves from the wrong root. To reproduce Pages:

```bash
npm run build:pages
mkdir -p /tmp/pgsite && ln -sfn "$PWD/dist/pelegames/browser" /tmp/pgsite/Pelleg
npx --yes http-server /tmp/pgsite -p 4300 -c-1
# open http://localhost:4300/Pelleg/
```

Verified this way: `<base href="/Pelleg/">`, all fonts/icons/manifest 200, the
service worker registering at scope `/Pelleg/` and taking control, and 23 entries
precached. Note `http-server` does not serve `404.html` on a miss the way Pages
does, so deep links are the one thing this setup cannot exercise.

## Scripts

| Script                | Does                                                    |
| --------------------- | ------------------------------------------------------- |
| `npm start`           | dev server                                              |
| `npm test`            | vitest                                                  |
| `npm run build`       | production build                                        |
| `npm run build:pages` | production build + base-href + `404.html` + `.nojekyll` |
| `npm run icons`       | regenerate app icons                                    |
| `npm run preview`     | serve `dist` at the root (no subpath)                   |
